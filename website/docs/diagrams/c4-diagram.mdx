---
title: C4 Diagram
---

C4 diagrams describe software architecture using people, software systems, containers, components, and relationships.

Pintora's C4 diagram syntax is macro-first. It is intended to be familiar to Mermaid C4 and C4-PlantUML users, while using Pintora's dagre-based automatic layout.

## System Context

```pintora play
C4Context
title: System Context

Person(customer, "Customer", "Uses online banking")
System(banking, "Internet Banking System", "Allows customers to view accounts")
System_Ext(email, "E-mail System", "Sends notifications")

Rel(customer, banking, "Uses", "HTTPS")
Rel(banking, email, "Sends e-mail", "SMTP")
```

## Container

```pintora play
C4Container
title: Internet Banking - Containers

Person(customer, "Customer", "A retail banking customer")
System_Boundary(banking, "Internet Banking System") {
  Container(web, "Web Application", "React", "Delivers the single-page app")
  Container(api, "API Application", "Spring Boot", "Handles business requests")
  ContainerDb(db, "Database", "PostgreSQL", "Stores account data")
}
System_Ext(email, "E-mail System", "Sends notifications")

Rel(customer, web, "Uses", "HTTPS")
Rel(web, api, "Calls", "JSON/HTTPS")
Rel(api, db, "Reads/Writes", "JDBC")
Rel(api, email, "Sends messages", "SMTP")
```

## Component

```pintora play
C4Component
title: API Application - Components

Container_Boundary(api, "API Application") {
  Component(controller, "Account Controller", "TypeScript", "Handles HTTP requests")
  Component(service, "Account Service", "TypeScript", "Applies business rules")
  ComponentDb(repository, "Account Repository", "TypeScript", "Reads account data")
}

Rel(controller, service, "Calls")
Rel(service, repository, "Reads")
```

## Dynamic

```pintora play
C4Dynamic
title: Sign-in Flow

Container(web, "Web Application", "React")
Container(api, "API Application", "Node.js")
ContainerDb(db, "Database", "PostgreSQL")

RelIndex(1, web, api, "Submits credentials", "JSON/HTTPS")
RelIndex(2, api, db, "Reads user record", "SQL")
RelIndex(3, api, web, "Returns session", "JSON/HTTPS")
```

## Deployment

```pintora play
C4Deployment
title: Production Deployment

Deployment_Node(region, "AWS Region", "us-east-1") {
  Node(cluster, "EKS Cluster", "Kubernetes") {
    Container(api, "API Application", "Node.js")
  }
  Node(databaseHost, "Database Host", "RDS") {
    ContainerDb(db, "Database", "PostgreSQL")
  }
}

Rel(api, db, "Reads/Writes", "SQL")
```

## Supported Macros

| Category      | Macros                                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Entries       | `C4Context`, `C4Container`, `C4Component`, `C4Dynamic`, `C4Deployment`, `c4Diagram`                                       |
| People        | `Person`, `Person_Ext`                                                                                                    |
| Systems       | `System`, `System_Ext`, `SystemDb`, `SystemQueue`                                                                         |
| Containers    | `Container`, `Container_Ext`, `ContainerDb`, `ContainerQueue`                                                             |
| Components    | `Component`, `Component_Ext`, `ComponentDb`, `ComponentQueue`                                                             |
| Boundaries    | `Boundary`, `Enterprise_Boundary`, `System_Boundary`, `Container_Boundary`, `Deployment_Node`, `Node`, `Node_L`, `Node_R` |
| Relationships | `Rel`, `BiRel`, `Rel_U`, `Rel_Up`, `Rel_D`, `Rel_Down`, `Rel_L`, `Rel_Left`, `Rel_R`, `Rel_Right`, `Rel_Back`, `RelIndex` |

## Arguments

Element macros use positional arguments:

```txt
Container(alias, "Label", "Technology", "Description")
```

Named arguments can be used for common optional fields:

```txt
Person(customer, "Customer", $descr="Uses the service", $tags="person,external", $link="https://example.com")
```

Relationship macros use:

```txt
Rel(sourceAlias, targetAlias, "Label", "Technology")
```

Dynamic relationship macros use:

```txt
RelIndex(index, sourceAlias, targetAlias, "Label", "Technology")
```

## Layout Notes

Pintora uses dagre automatic layout for C4 diagrams. The result may differ from PlantUML and Mermaid layouts.

Direction-specific relationship macros such as `Rel_R` are parsed as relationship metadata. They do not force exact manual placement.

## Unsupported C4-PlantUML Features

Pintora C4 does not run PlantUML preprocessing. These features are not part of the current implementation:

- `!include`, `!define`, procedures, and macro expansion
- Sprites and icon libraries
- Generated legends
- Full tag style declarations such as `AddElementTag` and `AddRelTag`
